# 所属と順位の年次報告

2026-11-11 の画面です。試合ごとの大きなフォームは使いません。前年度のカテゴリと最終順位だけを、所有者またはコーチが確認して提出します。

年度、期限、遅延提出、機能を止めないこと、インターネット上の情報だけでは提出にならないことは、`docs/official-results-reporting.md` と同じです。

## 所属

チーム登録の2画面目で、都道府県、カテゴリ、所属リーグ・連盟名を必須にします。カテゴリは U-6、U-8、U-10、U-12、U-13、U-14、U-15、U-18、一般、女子、シニアです。「所属なし」を選ぶと、他の欄は空のままで登録できます。

リーグと部は任意です。都・県リーグの1・2部は SS、3・4部は S、地域リーグの1・2部は A、3・4部は B、リーグなし・その他は C の目安になります。保存だけではチームの強さは変わりません。「このランクにする」を押したときだけ変わります。順位表の順位からは目安を出しません。

すでにあるチームには、所有者とコーチの次のログインで、閉じられる案内を出します。案内は機能を止めません。あとからチーム編集とマイページの「所属」で直せます。

## 結果ページ

所属を保存したあと、サーバがそのリーグの公開の結果ページを探します。検索 API は使いません。環境変数 `RESULTS_SEARCH_ENDPOINT` と `RESULTS_SEARCH_API_KEY` があるときだけ、その公開 https の検索を先に使います。無いときは、団体名に書かれた http または https の URL と、名前が一致したときだけの都道府県協会の公開 URL を見ます。

ページに順位表の語と団体名があるときだけ、その URL を結果ページにします。確信が低いとき、または見つからないときは「結果ページのURLを教えてください」と聞き、入力された URL を保存します。「所属なし」のときは探しません。

取得は公開の http / https だけです。認証情報付きの URL、localhost、プライベートアドレス、リンクローカル、メタデータ用アドレスは拒否します。DNS の結果も同じ基準で見ます。接続先はそのアドレスに固定します。robots.txt を見て、同じホストは1時間に8回までです。User-Agent は `SakamatchResultsBot/1.0 (+https://www.sakamatch.com/results)` です。

## クロール

保存済みの結果ページを、前回の取得から7日以上たっているものだけ取ります。対象年度のカテゴリと最終順位を候補として残し、URL、取得時刻、根拠の短い抜粋を保存します。候補だけでは提出になりません。失敗は取得履歴に残し、画面や他の機能は止めません。

Vercel Hobby の cron は1日1回までです。週1回の式は使わず、既存の毎日の `/api/cron/selection-crawler` が offset 0 のときだけ `/api/cron/results-standings` を起こします。専用の cron を足す場合も毎日の式にし、7日未満のページは処理しません。1回の実行は3チームで、続きは最大12回です。`vercel.json` は足していません。ダッシュボードの既存 cron を置き換えないためです。

## 提出

報告画面の初期値は前年度です。候補があるときは出典のリンク付きで欄に入ります。「この内容で提出」は、その候補と一致するときだけ通ります。「直して提出」ではカテゴリを選び、順位を選ぶか「順位なし・不明」にできます。候補が無いときは空の選択です。

古い試合行の表と取得履歴は残しています。このマイグレーションは追加だけで、表は落としません。

## 本番で必要な作業

1. `supabase/migrations/20261111193000_team_affiliation_standings.sql` を、`20261105214326` のあとで適用する。そのあと `supabase/migrations/20261112042135_team_affiliation_league_level.sql` を適用する。フォルダ全体の `supabase db push` はしない。古い表は落とさない。リーグの列は空のままで、既存チームの強さは変えない。
2. 新しい必須の環境変数はない。任意で `RESULTS_SEARCH_ENDPOINT`、`RESULTS_SEARCH_API_KEY`、`RESULTS_SEARCH_KEY_HEADER`。cron は既存の `CRON_SECRET`、`NEXT_PUBLIC_SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY` を使う。検索キーが無いときは、種の URL か入力を使う。service role が無いと候補は保存できない。所属と URL の保存はユーザーの RLS で動く。
3. cron は既存の selection-crawler が毎日起こす。別にするときはダッシュボードで `GET /api/cron/results-standings` を `0 18 * * *`（UTC、1日1回）にする。Hobby で週次の式が拒否されるので毎日にする。`/api/cron/selection-crawler` は残す。
4. マイグレーションのあとにアプリをデプロイする。列が無い間、ホームの案内は空になり、順位の提出は `schema_unavailable` を返す。ログインや試合は止まらない。
